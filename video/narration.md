# 시연 영상 내레이션 원고 (10분)

- 화면 구성은 `out/rough_cut.mp4`(무음 가편집본)와 같은 순서·길이다. 표의 시간은 `scripts/assemble_rough_cut.py`의 `TIMELINE`과 같다.
- 분량 기준: 1초에 약 5~6음절. 각 구간 원고는 구간 길이보다 약간 짧게 썼다.
- **[실시간]** 구간은 직접 녹화할 화면이다. 녹화 후 `TIMELINE`의 해당 항목을 `clip`으로 바꾸고 파일을 `out/`에 두면 된다.
- 수치는 보고서(`build/report.pdf`)와 같다. 휴머노이드는 방법당 18회(3세트 × 6회) 기준이며, 세트별 공통 시작 장면 1회는 평가 전 실행으로 제외한다.

---

## 1부. 개요 (0:00–1:50)

### 0:00–0:30 · 표지 (슬라이드 1)
안녕하십니까. AI 기반 Physical AI 작업 수행 검증 및 회귀 테스트 자동화 기술을 시연하겠습니다.
이 시스템은 로봇이 실패할 만한 테스트 환경을 LLM이 스스로 설계하도록 하고, 찾은 실패를 다시 실행할 수 있는 회귀 테스트로 남깁니다.
로봇팔과 휴머노이드, 두 종류의 로봇으로 검증했습니다.

### 0:30–0:55 · 배경과 문제 (슬라이드 2)
로봇팔, 자율 이동 로봇, VLA 모델 같은 Physical AI는 물체 위치나 장애물, 작업자 접근이 조금만 바뀌어도 같은 명령에서 실패할 수 있습니다.
지금은 사람이 예상 가능한 케이스를 직접 만들어 시험하기 때문에, 드문 실패나 성공과 실패의 경계를 체계적으로 찾기 어렵습니다.

### 0:55–1:15 · 평가 지표 (슬라이드 3)
평가 지표는 세 가지입니다. 실패 발견율 30% 이상, 같은 시도 횟수의 Random 테스트 대비 20% 이상 향상, 그리고 주요 실패 유형 6종 중 4종 이상 발견입니다.

### 1:15–1:50 · 시스템 구성 (슬라이드 4)
위쪽의 능동 실패 탐색, AFS에서 LLM이 이전 실행을 관측하고, 실패 가설을 세우고, 다음 환경을 제안합니다.
제안은 규칙 기반 검증을 통과해야만 실행됩니다.
테스트 대상 로봇은 블랙박스로 실행만 하고, 결과는 독립된 평가기가 판정해 기록으로 남깁니다.

## 2부. 구현 시연 (1:50–5:40)

### 1:50–2:11 · 입력 (클립 `input_settings.mp4`)
> 화면: 휴머노이드 본 실험 한 세트(시드 253785482) 탐색의 실제 설정값(`afs/protocol.json`, 첫 제안 `context.json`의 `task_contract`·`scene_domain.axes`).

먼저 입력입니다. 작업 목표와 바꿀 수 있는 환경 요소의 범위, 시도 횟수를 정합니다.
휴머노이드 실험은 상자, 바닥, 통로 폭, 장애물, 사람의 움직임까지 21개의 변수를 바꿀 수 있습니다.

### 2:11–2:36 · AFS 입력과 출력 (슬라이드 6)
AFS는 영상 대신 텍스트로 된 행동 기록을 읽습니다. 경로 계획에 실패했는지, 밀기 요청이 어떻게 됐는지, 접촉이 몇 초였는지 같은 것들입니다.
그리고 근거 실행, 바꿀 값, 실패 가설, 예상 실패 유형, 반증 조건을 정해진 형식으로 내놓습니다.

### 2:36–3:26 · AFS 한 바퀴 (클립 `afs_loop_box_shift.mp4`)
> 화면: 휴머노이드 본 실험 한 세트(시드 253785482)의 실제 기록 4장(① 시작 장면 실행 관측 ② AFS 요청·응답 ③ 규칙 검증 ④ 실행 결과). 환경 생성 그림·휴머노이드 클립과 같은 사례.
> 출처: `seed_253785482/reports/*/253785482_afs_proposals.json` 첫 제안, `afs/attempts/attempt_0000{0,1}/rollout/result.json`

실제 기록으로 한 바퀴를 따라가 보겠습니다. 시작 장면에서 로봇은 네 번의 판단으로 목표에 도착했고, 상자는 움직이지 않았습니다.
AFS는 이 기록을 읽고 51초 만에 응답했습니다. 상자를 목표 한가운데로 옮기면 써 보지 않은 행동이 필요해 성공 패턴이 깨질 수 있다는 가설과 함께, 상자 위치 하나만 바꾸자고 제안했습니다. 로봇이 상자를 밀어내고 도착하면 가설이 틀린 것이라는 반증 조건도 함께 냈습니다.
검증기는 근거 실행이 실제로 있는지, 바꾼 값이 하나인지, 나머지가 그대로인지 확인한 뒤 실행을 허가했고, 결과는 예상대로 목표 위치 점유 실패였습니다.

### 3:26–4:01 · 환경 생성 (그림 `assets/env_generation.png`)
검증을 통과한 값으로 환경 생성기가 물리 시뮬레이션 모델, 이동 지도, 3D 장면 그래프를 함께 만듭니다.
위는 시작 장면, 아래는 AFS가 제안한 대로 상자 하나만 통로 가장자리에서 중앙으로 옮긴 장면입니다.
상자 좌표가 바뀌고, 이동 지도에서 목표까지의 경로가 사라지며, 장면 그래프에서 상자와 목표의 관계가 ‘비어 있음’에서 ‘완전 점유’로 바뀝니다.
세 표현이 서로 맞는지 실행 전에 검사합니다.

### 4:01–4:47 · 휴머노이드 사례 (클립 `humanoid_baseline_vs_box_shift.mp4`)
방금 본 두 실행을 실제 영상으로 보겠습니다. 먼저 시작 장면, 이어서 상자를 옮긴 장면입니다.
로봇은 상자를 밀어내려고 북쪽으로 돌아가 정렬하지만, 밀기 요청은 실행되지 않고, 다시 돌아가려 해도 목표 지점이 막혀 있습니다.
결국 허용된 판단 20회를 모두 쓰고 목표 0.85미터 앞에서 멈췄고, 평가기는 이를 목표 위치 점유로 판정했습니다.
영상은 LLM 응답을 기다리는 구간을 30배, 로봇이 움직이는 구간을 4배로 재생했습니다.

### 4:47–5:02 · 회귀 재실행 (클립 `regression_rerun_3x.mp4`)
찾은 실패는 기록과 함께 저장되어 다시 실행할 수 있습니다. 같은 환경을 세 번 실행하면 접촉 시간과 물리 기록까지 똑같은 실패가 재현됩니다.
개발 단계 점검에서는 원래 실패 10건이 모두 재현됐습니다.

### 5:02–5:28 · 회귀 실행기 실제 동작 (클립 `demo_regression_run.mp4`)
> 화면: 앞 4초는 화면 녹화(`.mov`)에서 터미널 부분만 자른 명령 실행 장면(서버 IP가 보이는 상태 표시줄은 잘라 냄), 이어서 `demo_recording_20261025_v2/demo.mp4`(시연 전용 실행, 평가 미포함). 회귀 실행기로 저장된 시작 장면(AFS 제안의 근거가 된 그 장면)을 재실행하는 터미널·시뮬레이터 화면. LLM 응답 2회 뒤 중단해 '판정 불가'로 기록됨.

서버에서 명령 하나로 회귀 실행기를 실행합니다. 저장된 사례를 그대로 불러와 다시 실행하고, 이전 결과와 비교해 유지, 퇴행, 개선으로 분류합니다.
도중에 멈추거나 API 오류로 끝난 실행은 실패로 세지 않고 판정 불가로 따로 남깁니다.

### 5:28–5:40 · 회귀 재실행 결과 (클립 `regression_qwen_card.mp4`)
> 결과 수치 출처: `experiment_results_qwen38/humanoid_qwen38_20261025_v1/comparison_reports/20261025T065019_707680Z/summary.json`, 추가 1회는 `normal_429_followup_once_v1/` (보고서 표 13). 로봇 판단 횟수는 실행별 `decisions.jsonl`에서 센 값.

로봇의 LLM을 Qwen으로 바꿔 돌려 보니 두 사례의 결과는 그대로였지만, 같은 장면을 끝내는 데 로봇 판단을 두 배 가까이 썼습니다.
회귀 테스트는 결과와 함께 자원 사용량도 봐야 합니다.

## 3부. 기술과 성과 (5:40–9:40)

### 5:40–5:55 · 주요 적용 기술 (슬라이드 5)
장면은 파라미터 벡터와 장면 그래프, 이동 지도로 표현하고, 물리 시뮬레이션은 MuJoCo를 썼습니다.
탐색은 GPT-6 Luna 계열 모델이, 판정은 규칙 기반 검출기가 맡습니다.

### 5:55–6:15 · 두 종류의 테스트 대상 (슬라이드 7)
실험은 두 가지입니다. 첫째는 Franka사의 Panda 로봇팔을 NVIDIA의 VLA 정책 GR00T가 움직이는 집어 놓기 작업이고, 둘째는 Unitree사의 G1 휴머노이드를 LLM Agent가 조종하는 이동 작업입니다.
두 방법은 같은 로봇, 같은 범위, 같은 시도 횟수로 비교했습니다.

### 6:15–6:33 · 로봇팔 12 vs 12 (클립 `arm_grid_12v12.mp4`)
왼쪽이 AFS, 오른쪽이 Random 테스트입니다. 위 두 줄은 두 방법이 같은 장면을 쓰는 공통 시작 장면이고, 아래 두 줄이 평가 실행입니다.
AFS는 6번 모두 실패 사례를 찾았고, Random 테스트는 1번이었습니다.

### 6:33–7:07 · 결과 (슬라이드 8)
로봇팔에서 AFS의 실패 발견율은 100%로, Random 테스트 16.7%의 6배입니다. 다만 6건 중 3건은 이미 실패한 장면을 다시 고른 것입니다.
휴머노이드는 세트당 6회, 두 방법 각 18회로 평가했습니다.
AFS 33.3% 대 Random 테스트 11.1%로 3배였고, 세 세트 모두에서 2건씩 꾸준히 실패 사례를 찾았습니다.

### 7:07–7:25 · LIBERO 과제 묶음별 확인 (클립 `arm_libero_suites.mp4`)
LIBERO는 과제 묶음이 여럿이어서, Object와 Goal에서도 대표 과제를 하나씩 골라 세 세트를 돌렸습니다.
버터 옮기기에서는 AFS 88.9%, Random 테스트 33.3%였지만, 제안 대부분이 범위 끝값 조합이었습니다. 서랍 열기는 정책이 기본 장면부터 실패해 비교할 수 없었습니다.

### 7:25–7:39 · 휴머노이드 다른 배치 (클립 `humanoid_venues.mp4`)
휴머노이드도 창고, 사무실, 교차로 배치에서 공통 시작 장면 외에 각 방법을 두 번씩 실행했습니다.
창고는 2 대 0, 교차로는 1 대 1이었고, 사무실은 시작 장면부터 실패해 비교하지 못했습니다.

### 7:39–7:55 · 창고: 사람 접촉 후 넘어짐 (클립 `humanoid_warehouse_fall.mp4`)
창고에서는 새 유형이 나왔습니다. 이동이 막혀 LLM 응답을 기다리던 로봇에 사람이 부딪혀 넘어졌습니다.
예상은 이동 정체여서 가설은 빗나갔지만, 응답을 기다리는 시간이 안전 문제가 될 수 있음을 보여 줍니다.

### 7:55–8:18 · 가설은 얼마나 맞았나 (슬라이드 9)
휴머노이드 본 실험에서 목표 위치 점유를 예상한 3건은 모두 맞았지만, 충돌이나 이동 정체를 노린 9건은 모두 성공으로 끝났습니다.
이미 관측한 실패 메커니즘을 겨냥할 때는 잘 맞고, 아직 보지 못한 유형을 겨냥할 때는 빗나갔습니다.

### 8:18–8:32 · 높이 경계 (클립 `arm_height_12v14cm.mp4`)
AFS가 찾은 실패의 원인을 확인하려고, 장애물 높이만 바꿔 봤습니다. 12센티미터에서는 성공, 14센티미터에서는 실패입니다.

### 8:32–8:45 · 접시 경계 (클립 `arm_plate_shift_375v50.mp4`)
접시 위치도 같은 방식으로 확인했습니다. 37.5%까지 옮기면 성공, 50%에서는 접시 8.7센티미터 앞에서 실패합니다.

### 8:45–9:05 · 경계 그래프 (슬라이드 10)
정리하면 이 정책은 장애물 높이 12에서 14센티미터, 접시 이동 37.5에서 50% 사이에서 결과가 바뀝니다.
배포 전에 어떤 조건을 먼저 점검해야 하는지 알려 주는 정보입니다.

### 9:05–9:25 · 실패 유형 (슬라이드 11)
실패 유형은 초기 6종 중 충돌, 장애물 간섭, 목표 위치 점유, 작업자 안전 위험의 4종을 발견했고, 도달 불가는 부분적으로 관측했습니다. 확장 유형인 넘어짐도 창고 배치에서 관측했습니다.

### 9:25–9:40 · 목표 달성 (슬라이드 12)
실패 발견율과 Random 테스트 대비 향상 목표는 두 실험 모두에서 달성했고, 실패 유형도 4종을 찾았습니다. 장면 구조화와 행동 기반 탐색, 회귀 테스트 자산화도 구현했습니다.

## 마무리 (9:40–10:00)

### 9:40–10:00 · 마무리 (슬라이드 13)
이 시스템은 실패를 기다리지 않고 찾아서 남깁니다.
행동 기록을 읽는 LLM이 다음 시험을 설계해 Random 테스트보다 3배 이상 많은 실패 사례를 찾았고, 찾은 실패는 정책이나 배치가 바뀔 때마다 다시 확인할 수 있는 회귀 테스트가 됩니다.
감사합니다.
